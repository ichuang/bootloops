# Composable high-rate quantum error correction

**Extend `ftqc_codes` to turn finite code constructions into verified CSS blocks with addressable logical qubits.** Give the same block to the existing measurement, schedule, fault and decoder tools. The first study should prepare a pair of logical slots, measure one through a lifted-product surgery gadget, then use that signed result to control a read on the surviving slot. Success means another user can replay the whole experiment, substitute a compatible construction or decoder, and see which conclusions and resource counts change.

The original controls were measured at `0c0af60`. The library survey accounts for Magic landing in integration at `827e0b9`. Begin with one optional qLDPC exporter and a BootLoops importer for checks and logicals. Three tested exchanges and the build-versus-reuse decisions are in the [open-source QEC library survey](qec-library-survey.md). Milestones below describe proposed changes. The repositories' current interfaces and first controls are identified explicitly. [Tool boundaries](../tools/FTQC.md) · [Prior surgery milestones and open work](extractor-surgery.md)

## Start from two existing representations

Codes accepts a `CSSCode` with ordered binary X and Z check rows. Its existing SHA-256 binds the width and ordered rows. Its receipt records finite distance intervals and the evidence behind their endpoints. Extractors already has HGP algebra, a cyclic lifted product over polynomial masks, the radial-90 matrices and a dense rank-one radial surgery map. Gadgets and Extractors already know how to verify signed surgery and installed operations. The missing piece is a public, verified path from the algebraic description **and a chosen logical basis** into those consumers. [Codes](../tools/ftqc_codes/codes.py) · [HGP algebra](../tools/ftqc_extractors/algebra.py) · [Lifted products and radial map](../tools/ftqc_extractors/surgery_products.py) · [Block addressing](../tools/ftqc_extractors/block_map.py)

These controls were recomputed on the integration baseline. Fingerprints are prefixes of the existing ordered-matrix digest. The last column is the largest supplied generator weight. Redundant check rows and their order matter to a syndrome circuit.

## 1. Make a finite construction replayable in Codes

First import an external finite instance, validate its checks and preserve its supplied logicals as candidates for step 2. Then extract the pure HGP and cyclic-product matrix builders into Codes. Keep the existing Extractors functions as compatibility entry points, preserving signatures, transpose convention, ordering and return types. Keep maps, wiring and schedules in Extractors. Extend the existing loader and `spec` command with tagged construction JSON. Continue accepting legacy matrix JSON, named families and both currently supported code-receipt formats. The new Python and CLI routes should call the same constructor. [CLI and error conventions](../tools/ftqc_codes/__main__.py) · [Existing evidence legs](../tools/ftqc_codes/GUIDE.md)

For cyclic lifts record the lift order, rectangular seed shapes, coefficients in GF(2)[x]/(x^L−1), transpose/inversion convention and the order of cell and group coordinates. For a general group action require explicit, validated left and right permutations and their multiplication convention. Estimate expanded rows, columns, nonzeros and output size before allocating. Expand sparse supports into Codes' bit rows for exact checks. Preserve redundant physical checks in exports even if rank computation internally reduces them.

Add a versioned **construction receipt alongside** the existing static receipt. It should contain the source paper/version and table, equation or released artifact for the chosen instance, immutable seed inputs, generator convention, ordered matrix digest, ranks, k, rate k/n, row/column weight distributions and reference to the static receipt. Hash the canonical construction payload separately because the current matrix digest deliberately omits metadata. Verify by re-expanding and checking commutation and k = n − rank(HX) − rank(HZ). For imported matrices record their source hash and classify ancestry as supplied until the generator reproduces them. Serialize exact rates as integer pairs. Give paper values, finite witnesses, proved exclusion bounds and simulation estimates distinct fields.

**Acceptance.** Match all three controls above row for row, and cross-check the six-qubit fixture against an independently expanded circulant matrix. Compare exact small X/Z distances to direct enumeration of each normalizer modulo its stabilizers. Include rectangular seeds, repeated coefficients that cancel, and an asymmetric seed that detects reversing a shift. Reject malformed shapes and inconsistent claimed actions. A search that exhausts its budget returns the attained interval and work count. Existing `spec`, `certify` and `verify --full` must still accept banked fixtures.

## 2. Issue a logical basis that a consumer can use

For any finite CSS input, derive X representatives in ker(HZ)/row(HX) and Z representatives in ker(HX)/row(HZ). Pair them by elimination on their overlap matrix. Accept independently proposed, lower-weight bases through the same verifier. Record ordered slot names, physical representatives, signs, coordinate ordering and parent matrix digest in a basis receipt. Verify membership, dimensions, independence and the identity X/Z pairing. Bind consumers to the basis digest as well as the code digest. To change representatives or relabel a basis, supply the induced logical transformation and stabilizer dressings and verify both against the physical rows. This lets two papers choose different logicals for the same memory without silently changing the program.

On odd-order Abelian lifts, add Lee's character packets and reciprocal-packet trace pairing as a basis producer. Cross-check the result with binary elimination. For canonical cyclic families, verify the physical permutation, induced logical action and orbit of each seed before using Zheng et al.'s reusable measurements. Check coverage by the rank and labels actually obtained. For group-extension lifts, check the chain maps against both boundary operators and calculate the induced action on logical classes before moving a gadget between block sizes. [Logical spectroscopy](https://arxiv.org/abs/2607.05386) · [Canonical lifted-product logic](https://arxiv.org/abs/2607.28605) · [Lifting lifted products](https://arxiv.org/abs/2607.28621)

**Acceptance.** On the six-qubit control, show that a slot swap preserves the code digest yet changes which physical measurement implements the requested logical. Test a valid stabilizer dressing, a wrong sign in a mixed-Pauli measurement, a duplicated slot and a seed orbit that covers only part of a block. Keep binary elimination available for even-order groups. The spectral producer must check its odd-order premise.

## 3. Admit paper families through the same interface

Use external generators or published matrices for the first instance in each row. Implement a native specialization when needed to reproduce ancestry, produce a missing construction, or remove a measured bottleneck. Land the first two rows before expanding the family catalog. Each new family needs a specified finite input that another implementation can reconstruct, an independent algebraic cross-check on a small instance and one downstream study. Archive the exact paper revision and coordinate conversion used by that study.

| Scientific result | Implementation and finite comparison |
|---|---|
| Hypergraph and lifted products | Recover Tillich–Zémor at the trivial lift and the cyclic controls at nontrivial lift. Use Panteleev–Kalachev for the construction and asymptotic hypotheses. For a selected finite lift, replay both a low-weight logical witness and every claimed lower-bound proof. Use Raveendran et al. to select ambiguous finite-distance cases. [HGP](https://arxiv.org/abs/0903.0566) · [Lifted product](https://arxiv.org/abs/2012.04068) · [Good qLDPC families](https://arxiv.org/abs/2111.03654) · [Finite LP distances](https://arxiv.org/abs/2503.07567) |
| Bicycle and radial codes | Use BB144 as the ordered-matrix and circuit control. Build the two-block group-algebra specialization and compare its cyclic/Abelian instances to existing Codes output under explicit coordinate maps. Port a published radial measurement map and compare it with the existing dense radial-90 reference under identical rounds and boundaries. [Two-block algebra](https://arxiv.org/abs/2306.16400) · [BB memory](https://arxiv.org/abs/2308.07915) · [Radial codes](https://arxiv.org/abs/2406.14445) · [Lifted surgery](https://arxiv.org/abs/2609.11723) |
| Balanced products and quantum Tanner codes | Import a QuantumExpanders.jl Tanner fixture with its ordered local neighborhoods. For a native ancestry check, implement the balanced quotient using explicit group orbits on chain coordinates. Test a small nonabelian action where left and right multiplication differ. Construct Tanner checks from the left-right Cayley complex and its local codes. Check incidences, local constraints, ranks and pairing. Pass the local neighborhoods to Decoders. Tag expansion, robustness and decoding hypotheses individually as checked or assumed. [Balanced product](https://arxiv.org/abs/2012.09271) · [Quantum Tanner codes](https://arxiv.org/abs/2202.13641) · [Linear-time decoding](https://arxiv.org/abs/2206.07750) · [Single-shot decoding](https://arxiv.org/abs/2306.12470) |
| Ultra-high-rate CSS constructions | Start with the authors’ published binary check and basis matrices. To reproduce construction ancestry, expand a pair-partition seed into circulant permutation matrices. Check CSS orthogonality directly. Implement symmetry-reduced distance exclusion only with replayable orbit coverage and check it against unrestricted enumeration on small lifts. Target the published [[256,68,12]] block, then the [[1152,580,12]] measurement study, with the distances recorded as paper targets until replayed. Lee et al.'s compact non-CSS examples need a separate symplectic-code extension. [Pair partitions](https://arxiv.org/abs/2607.14091) · [Design principles](https://arxiv.org/abs/2609.30069) · [Parallel measurements](https://arxiv.org/abs/2610.06749) |

## 4. Compose a study with existing tool owners

| Owner | Proposed handoff and check |
|---|---|
| Codes → Gadgets / Extractors | Export ordered checks, slot basis and any verified symmetry or chain map. An adapter builds the native signed target for Gadgets. Extractors installs it on physical blocks, ports and couplers. It records physical measurement IDs, surviving logicals, frame updates and shared ancilla lifetimes. Replay the signed instrument for every admitted branch. [Gadgets](../tools/ftqc_gadgets/SURGERY.md) · [Installed surgery](../tools/ftqc_extractors/installed_surgery.py) |
| Extractors / Gadgets → Faults | Flatten the actual schedule with idles, routing, detectors, protected observables and unique physical fault-location IDs across boundaries. Use the audit engine for exclusion/witness intervals and ZX for supported equivalence claims. A different coupler inventory or round schedule gets its own circuit evidence. [Faults](../tools/ftqc_faults/GUIDE.md) |
| Faults → Decoders | Supply the same detector/observable order and correlated alternatives per location to BP+OSD and a family-specific decoder. Start with exact small-fault enumeration. For Tanner single-shot studies implement the local update rule from the selected paper, inject data and syndrome errors, then check the residual modulo stabilizers over consecutive rounds. Track operational radius, trapping witnesses and sampled logical failure separately. [Decoder interfaces](../tools/ftqc_decoders/GUIDE.md) · [Finite-length BP+OSD](https://arxiv.org/abs/1904.02703) |
| Gadgets / Extractors → Compose | Reverify the producer receipts. Match block, slot order, symplectic frame, public-bit signs, open-input tolerance, accepted outputs and residual law. Trace a shared fault through both operations exactly once. Report a conditional result when a premise is supplied. Run the whole tiny schedule independently and compare branch-by-branch. [Composition](../tools/ftqc_compose/GUIDE.md) |
| Compose / Decoders → Uncompute | Price a workload only after supplying its actual reaction depth, decoder latency model and accepted-output consumption. Report peak data/ancilla counts, physical qubit-ticks, measurement rounds and stalls. Compare hardware layouts on the same logical workload and physical error model. [Neutral-atom schedules](https://arxiv.org/abs/2308.08648) · [Bicycle instructions](https://arxiv.org/abs/2506.03094) · [Multi-tier layouts](https://arxiv.org/abs/2611.20410) |

**First end-to-end experiment.** Install the six-qubit cyclic memory using the generic verified basis. Measure logical Z on slot 0 nondestructively, then use its recorded bit to set the sign of an X read on slot 1. Include encoded references, both first-read outcomes and a nontrivial input Pauli frame. Build a direct physical control circuit and compare joint readout bits, remaining encoded state and frame for every branch. Repeat with an equivalent dressed basis and explicit conversion. A slot swap, stale digest, reversed record sign or omitted boundary idle must fail its relevant check. Once this passes, substitute a verified translated-seed gadget on a compatible canonical LP instance. Compare it to ordinary repeated surgery on that same instance. Report any extra couplers, rounds or ancillas used by either implementation.

**Scale-up experiment.** On BB144 replay the existing published-memory and extractors controls with different decoders. On radial-90 run the optimized and dense maps at matched boundaries. On the pair-partition block compare a parallel orbit measurement to a serial implementation of the *same signed subgroup*. Distinguish k/n from total physical qubits per surviving logical, and static distance from phenomenological, circuit and decoded performance. For simulations record model, idle policy, decoder configuration/version, random seed, shots, failures, uncertainty interval and conditioning. Larger studies can deliver a witness or a resource estimate even when distance exclusion remains open. [BB144 integration control](../tools/FTQC.md) · [Parallel high-rate logic](https://arxiv.org/abs/2610.06749)

## 5. Join Magic at its existing boundary

Magic landed on `ftqc_integration` at `827e0b9`. It supplies verified source receipts and bridge summaries. The next work is consumer replay, physical delivery into a named logical slot, and composition of accepted errors. The eight-qubit HGP control can proceed while the addressable LP block is being built. [Magic handoff implementation plan](magic-handoff.md)

The first joint test should feed a verified single-output T source into an addressable slot on a tiny LP block. Verify the source spec and receipt through Magic. Have the consumer supply the encoder or transfer circuit, physical port, slot, sign, frame, arrival time and acceptance bit. Replay injection and its feed-forward branches, then measure the data slot. Compose must justify conversion from the source's stated quality metric under the actual injection protocol, propagate accepted and unnormalized failure with their conditioning, and include transfer faults and retries. Reconcile factory wire-ticks with concurrently live memory and transfer ancillas. A source descriptor or scalar infidelity alone leaves the end-to-end channel claim open. Use the existing logical-T test as the control. Reject a CCZ-for-T substitution, reversed frame and use of two correlated outputs as independent. Later batch studies must provide a verified joint law or physically justify distinct instances and their noise assumptions. [Existing logical-T test](../tools/ftqc_compose/test_logical_t.py) · [Source descriptor](https://github.com/ichuang/bootloops/blob/7122787/tools/ftqc_magic/bridges/extractors_bridge.py)

## Implementation status

All five milestones above have landed on `ftqc_integration`:

- **§1 Construction & interchange (`tools/ftqc_codes/{interchange,constructions,producers/qldpc_export}.py`)**: `ftqc_codes-import-1` sparse JSON / MatrixMarket `.mtx` loader with verified push coordinate maps (`perm_q`, `perm_hx`, `perm_hz`), pre-allocation size caps, native `hgp` / `lifted_product` / `group_lifted_product` / `radial90` / `cpm_pair_partition` builders, `ftqc_codes-construction-1` receipts, and byte-identical compatibility wrappers in `ftqc_extractors/{algebra,surgery_products}.py`. Banked exchange fixtures cover `qLDPC` `BB144` (`0ae98ac8a6e5`), coordinate-mapped `LP(6,2)` (`c6860dd462fe`), Okada–Kasai `[[256,64,<=12]]` `.mtx` (`ae0e0d3f792d`), and `QuantumExpanders.jl` `D_8` `[[36,8,3]]` (`2a4c9af20216`).
- **§2 Addressable bases & lift symmetries (`tools/ftqc_codes/{basis,symmetry}.py`)**: `ftqc_codes-basis-1` generic binary overlap pairing, external basis verification, mod-4 mixed-Pauli (`Y`) embeddings, stabilizer dressings and symplectic basis conversions (`verify_basis_transform`), Lee odd-order Abelian spectroscopy (`arXiv:2607.05386`, failing closed on even orders), Zheng et al. cyclic LP seed-orbit rank/slot coverage (`arXiv:2607.28605`), and Hirasaki–Lee cyclic extension chain maps (`arXiv:2607.28621`).
- **§3 Paper families, Leg G orbit search & Tanner single-shot decoding (`tools/ftqc_codes/{families_highrate,orbit_minweight}.py`, `tools/ftqc_decoders/tanner_local.py`)**: `L=1` HGP equivalence, Raveendran finite LP (`arXiv:2503.07567`), Abelian/non-Abelian `2BGA` reconciled with `codes.bb`, non-Abelian balanced products (`arXiv:2012.09271`), Quantum Tanner square-complex & lifted left-right codes (`[[36,8,3]]`, `[[288,8]]`, with `"checked"` vs `"assumed"` hypothesis tags), CPM/APM pair-partition codes (`PP184`, `PP256`, `PP576`, `APM1152`), Leg G symmetry-reduced minimum-weight exclusion, zero-float `tanner_local` single-shot decoding, and sparse `scipy.sparse.csc_matrix` external solver handoff.
- **§4 Composed surgery, reaction-stall pricing & scale-up studies (`tools/ftqc_extractors/addressable_surgery.py`, `tools/ftqc_uncompute/adapters/ftqc_bridge.py`)**: end-to-end 64-branch `LP(6,2)` replay (base + dressed basis + 4 negative controls), translated-seed substitution on `LP(8,4)`, full `Faults -> Decoders -> Compose -> Uncompute` pipeline (`estimate_reaction_decoder_latency` across 3 hardware layouts), and banked `studies/high-rate/` artifacts (`BB144` decoders, `radial90` $\mathbb{Z}_5$-homotopy sparsification vs dense reference, and `PP256` `[[576,34,12]]` parallel 34-logical orbit surgery vs 34-step serial subgroup measurement).
- **§5 Addressable LP Magic handoff (`tools/ftqc_compose/addressable_magic.py`)**: verified `bk_15_1_3_t` single-output `T` delivery via `occupied_swap` into `LP(6,2)` slot `q1` (preserving untouched `q0` + Bell reference), 4-branch adaptive consumption + Kraus/half-diamond metric conversion proof, conditioned & unnormalized failure bounds with retry occupancy, wire-tick reconciliation against the 8-qubit HGP `consume_t` control, and negative controls (`CCZ`-for-`T`, unproved reversed frame, and `BATCH_CORRELATED` batch misused as independent).
- **Explicitly scoped / deferred**: non-CSS / halved symplectic pair-partition codes fail closed with a named symplectic-extension refusal; spectral Ramanujan / coboundary expansion hypotheses are tagged `"assumed"` unless independently proved; and unreplayed distances on large blocks (`PP256` $d=12$, `PP576` $d=18$, `APM1152` $d=12$) remain in `claims.paper_claims` distinct from `proved_lower`.
