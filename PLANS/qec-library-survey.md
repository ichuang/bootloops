# Open-source QEC software for the high-rate FTQC plan

Surveyed 27 November 2026. **Start with Python qLDPC as an optional producer of finite codes and logical operators.** A single import path for ordered binary CSS matrices and logical representatives buys more coverage than a new BootLoops constructor for each paper. The table distinguishes libraries worth integrating from independent tools worth running on selected studies. Three exchange experiments below establish what works on actual inputs. [Implementation plan](high-rate-qec.md)

## Tools and their best uses

| Software | What it supplies | Decision for BootLoops |
|---|---|---|
| Python **qLDPC** (Apache-2.0) | HGPCode, LPCode, BBCode and QTCode, group-ring seeds, physical check matrices, logical representatives and qubit memory circuits. The package also handles qudits and subsystem codes. | First external producer. Export binary stabilizer CSS instances through one adapter. Use supplied logicals immediately after checking them. Compare an upstream memory circuit against a native schedule only after matching rounds, boundaries and noise. [Project and examples](https://github.com/qLDPCOrg/qLDPC) |
| **QuantumExpanders.jl** and **QuantumClifford.jl** (Julia, MIT) | The former builds square-complex and left/right-action quantum Tanner codes with Oscar.jl. Its documented nonabelian example has 288 physical and eight logical qubits. The latter provides stabilizer algebra and CSS distance optimization, including MIP. | First independent Tanner reference. Export one fixed instance with group action, seed ordering and local checks. Compare ranks and stabilizer spaces after an explicit coordinate map. Use an optimizer's candidate word as a witness. A certified lower bound needs evidence the verifier can replay. [Tanner library](https://github.com/QuantumSavory/QuantumExpanders.jl/tree/71058f87fc91c0d1f16e8932769a990b3e5609ef) · [ECC algorithms](https://qc.quantumsavory.org/stable/ECC_API/) |
| **Pair-partition construction and logical-basis archives** | Okada and Kasai release generators, sparse binary matrices, complete paired logicals, distance records and witnesses. The basis archive distinguishes software (MIT) from numerical data (CC0). | Import the four binary matrices and witness supports directly. Use a supplied basis to start the surgery study before implementing basis search. Check the exact block identity against the operations paper. The 256-qubit fixture tested below has 64 slots, while the plan's target has 68. [Construction software](https://github.com/kasaikenta/pair-partition-cpm-css-codes) · [Pinned basis and data archive](https://github.com/kasaikenta/canonical-logical-bases-pp-codes/tree/d10faecead37ad9c5044a5308f52cbcb524235c4) |

The latter generates HGP controls and extraction circuits, and documents a sparse check format. | Use the authors' BB pipeline as a second reference for gate order, terminal syndrome and failure accounting. Use exp_ldpc for a larger HGP fixture. Run exp_ldpc separately because it also uses the Python module name qldpc. [BB reference](https://github.com/sbravyi/BivariateBicycleCodes) · [HGP generator and file format](https://github.com/qldpc/exp_ldpc) |
| **SSIP** (Python, MIT) | Computes CSS code surgery constructions and algebraic merge data. | Import a small external merge into Gadgets as a competitor to the current mapping-cone implementation. Check maps, measured subgroup and surviving logicals, then construct and audit a physical schedule. This supplies the importer already identified in the surgery plan. | **GAP QDistRnd** (GPL-2.0) | Randomized minimum-weight search for CSS and more general stabilizer codes, with a Matrix Market-based interchange format. | Optional offline witness search for larger LP instances. Export candidate support, Pauli sector, seed and budget. Recompute weight, commutation and nontriviality in Codes. Retain the prior lower bound on timeout or apparent convergence. [QDistRnd](https://github.com/QEC-pages/QDistRnd) |
| **Stim / Sinter**, **ldpc**, **PyMatching**, **Tesseract** | Clifford circuit sampling and detector error models, repeated statistical trials, BP+OSD/BP+LSD, graph matching and search-based decoding. | Reuse the Faults exporter and Decoders' audited external backends. Reuse one set of detector samples for decoder comparisons. Preserve correlated alternatives and hyperedges. The existing PyMatching adapter requires at most two triggered detectors per mechanism. At large sizes its matrix-based path and the ldpc adapter currently allocate dense arrays, so profile memory and test sparse input support before scaling. PanQEC includes topological-code visualizations. bp_osd includes CSS and HGP examples alongside decoding. | Useful for surface-code controls or reproducing an older study's conventions. ## Three actual exchanges

The first two tests used qLDPC 0.2.9, Python 3.12.14, NumPy 2.2.6 and SciPy 1.15.3. The PyPI resolver initially installed NumPy 2.5.5, with which importing this qLDPC release failed at the RingArray declaration. Prepending BootLoops' tools directory to the producer's Python path also resolves the name galois to the BootLoops package instead of the finite-field dependency. Run the exporter in an isolated interpreter with a locked environment and exchange a data file. The consumer can replay the file with standard-library Python alone. The other libraries in the table were surveyed from upstream documentation.

| Experiment | Inputs and observed result |
|---|---|
| Gross code, BB144 | Built qLDPC BBCode with torus orders (12,6), A=x³+y+y² and B=y³+x+x². Converted matrix columns to bits with column zero least significant. Both ordered check lists matched BootLoops' bb144 digest, prefix 0ae98ac8a6e5. The independent rank calculation gave k=12. All twelve exported X/Z pairs commuted with opposite checks and had the identity pairing matrix. |
| Cyclic LP control | Built qLDPC LPCode with two one-entry seeds 1+x in GF(2)[C₃]. It gave n=6, k=2 and valid dual logicals. Its ordered-check digest began 6b6ef87d3693, versus c6860dd462fe in BootLoops. One exact external-to-native qubit map was (0,1,2,5,3,4), with X-check rows mapped to (0,1,2) and Z-check rows to (2,0,1). Both complete matrices then matched. The example demonstrates the need to transport qubit, syndrome and logical labels before composing circuits. |
| Published pair-partition block | Loaded Hx, Hz, Lx and Lz from the binary Matrix Market files for q4-j3-l8-p16-d12-w9-girth6 at d10faece. Converted the one-based matrix entries and the separately zero-based witness supports. BootLoops GF(2) checks gave n=256, k=64, maximum generator weight 9, commuting checks and 64 complete, dual logical pairs. Matrix digest prefix ae0e0d3f792d. Replayed an X logical of weight 12 and a Z logical of weight 21. This establishes d≤12. The archived lower-distance search was outside this test. [Exact input directory](https://github.com/kasaikenta/canonical-logical-bases-pp-codes/tree/d10faecead37ad9c5044a5308f52cbcb524235c4/codes/q4-j3-l8-p16-d12-w9-girth6) |

## Changes to implementation order

1. **Make the interchange the first deliverable.** Extend the current Codes JSON reader with a companion import manifest, preserving the existing ordered-matrix hash. Store producer version/revision, exact field and code type, parameters, source-file hashes, index base, row and column maps, and optional ordered logicals with signs or an explicit positive-representative convention. Export ordinary binary CSS matrices while retaining redundant physical checks. Accept versioned sparse row supports for large files. Check integer ranges, duplicate coordinates, width, ranks, orthogonality and logical pairing. Bank a reviewed export so installation and network access are optional during verification.
2. **Use the two matching tests above as different acceptance gates.** BB144 tests byte-for-byte convention agreement. The tiny LP tests a declared permutation and check order. Reject an altered physical map and a swapped single logical partner. Recheck a circuit under its own check order, even when two matrices generate the same stabilizer group. Add the 256-qubit published fixture to exercise sparse input and witness-only evidence.
3. **Advance addressable logic ahead of new native family generators.** Give one imported paired basis and one locally derived basis to the same signed-measurement consumer. For claimed low-weight or symmetry-adapted bases, verify weights, group action on physical representatives, logical orbit and measurement coverage. A generic paired basis suffices to start. Implement spectral decomposition or a new family generator when a specific experiment requires structured labels, unavailable instances, or independent derivation of the paper's recipe.
4. **Spend the saved implementation work on composition.** Replay signed measurement instruments, shared fault locations, conditioning, schedule conflicts and resource counts. Train or tune decoders on separate trials where applicable, then report matched outcomes from identical held-out circuits and noise. Keep a proof, a replayed witness and a sampled failure rate separately typed. The existing Magic bridges can supply factory data once a consumer validates its slot, frame, metric and fault boundary.
